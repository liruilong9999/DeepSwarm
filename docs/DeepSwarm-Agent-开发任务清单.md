# DeepSwarm Agent 开发任务清单

## 1. 文档用途

本文用于把 [DeepSwarm-Agent-设计文档.md](D:/code/git_code/ai/DeepSwarm/DeepSwarm_main/docs/DeepSwarm-Agent-设计文档.md) 拆成可由较弱编码模型逐项完成的本地任务。每次对话只执行一个任务，完成验收后再进入下一项。

本文不是新的架构设计。发生冲突时，事实源优先级如下：

1. 用户当前明确指令和仓库中的 `AGENTS.md`
2. `docs/DeepSwarm-Agent-设计文档.md`
3. `docs/DeepSeekAPI完整开发手册-官方文档只读.md`
4. 本任务清单中的当前任务边界

`docs/DeepSeekAPI完整开发手册-官方文档只读.md` 只能读取，禁止修改。Beta(测试版) 接口、Anthropic(另一种模型接口) 兼容接口、Prefix(前缀续写) 和 FIM(中间填充) 均不进入首版。

## 2. 执行规则

### 2.1 状态标记

- `[ ]`：未开始
- `[x]`：实现、测试和验收均已完成
- `[!]`：阻塞，必须在“完成记录”中写明可复现原因

只有任务自己的验收命令全部通过后，才能把 `[ ]` 改为 `[x]`。不得提前勾选，不得一次勾选多个尚未逐项验证的任务。

### 2.2 单任务纪律

1. 每次只执行一个 `TASK-xxx`，不顺手实现后续任务。
2. 开始前检查依赖任务是否均为 `[x]`，否则停止编码并报告。
3. 开始前运行 `git status --short`，保留用户已有修改，不覆盖、不回滚无关文件。
4. 先读当前任务指定文档和现有调用链，再给出不超过 5 步的本任务计划。
5. 只修改“允许修改”范围；确需越界时先停止并说明原因，不自行扩大范围。
6. 非平凡逻辑至少补一个能失败的自动化测试；安全、状态机、恢复和持久化不得省略异常测试。
7. 生产代码禁止使用 `unwrap()`、`expect()` 掩盖可恢复错误；测试和启动期不变量断言除外。
8. 新依赖必须服务当前任务，不为未来功能提前加入框架、Trait(特征)、工厂或插件系统。
9. 除非用户明确要求，不创建分支、不提交 Git(版本控制)、不修改设计决策。
10. 完成后更新当前任务的勾选状态和“完成记录”，记录修改文件、验收命令及结果。

### 2.3 固定实现基线

- 使用 Rust(编程语言) stable 和 Edition 2024。
- 使用 Cargo Workspace(Cargo 工作区)，依赖方向必须遵守设计文档第 16.4 节。
- 异步基石固定为 Tokio(异步运行时)；不引入 Actix、ractor 等 Actor(参与者模型) 框架。
- 本地守护进程接口使用 HTTP JSON；流式事件使用 SSE(Server-Sent Events，服务器推送事件)，事件契约保持与未来桌面客户端无关。
- DeepSeek 调用使用 `reqwest` 或等价的 Rust HTTP 客户端，只访问官方稳定地址。
- SQLite(轻量数据库) 使用 SQLx；必须开启 WAL(预写日志)，写入经有界单写队列提交。
- 分词使用 Rust `tokenizers` 读取仓库内资源，直接复现 Python 示例的 `tokenizer.encode(text)` 行为并统计 token ID 数量；不解析聊天模板，禁止把 Python 放入生产链路。
- Git 操作优先调用系统 Git CLI(命令行工具)，不引入 `libgit2`。
- CLI(命令行界面) 使用 `clap`；交互历史可使用一个成熟的小型行编辑库，不自行实现终端编辑器。
- 内部数据使用强类型，禁止用 `serde_json::Value` 代替可明确建模的核心状态。
- 会话记忆、项目记忆、归档记忆和摘要只保存在 SQLite。只有非记忆型大对象可落文件，SQLite 保存引用。
- 当前不实现桌面界面、分布式调度、插件市场、多供应商路由和常驻自动化调度器。

### 2.4 全局质量门禁

每项任务至少运行与改动相关的测试。阶段验收任务必须运行：

```powershell
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
git diff --check
```

## 9. 给编码模型的提示词

### 9.1 首次总控提示词

首次把下面内容发给编码模型；之后每次再发送第 9.2 节的单任务提示词。

```text
你将在 D:\code\git_code\ai\DeepSwarm\DeepSwarm_main 中开发 DeepSwarm。

开始前必须读取仓库中的 AGENTS.md（如果存在）、docs/DeepSwarm-Agent-开发任务清单.md、docs/DeepSwarm-Agent-设计文档.md。涉及 DeepSeek 时，只以 docs/DeepSeekAPI完整开发手册-官方文档只读.md 为调用规范，并且禁止修改该只读文档。涉及分词时读取 docs/refrence/deepseek_v3_tokenizer/deepseek_v3_tokenizer 下的资源。

你必须严格遵守任务清单：一次只执行一个 TASK，不实现后续任务，不做顺手重构，不创建桌面端、多模型抽象、插件系统或分布式能力。开始前检查依赖任务状态和 git status；保留已有修改。只修改当前任务允许的文件。若文档冲突、依赖未完成或必须越界，停止编码并报告，不要猜。

代码使用 Rust stable、Edition 2024 和主流 Rust 命名。优先标准库和现有依赖，不为未来需求增加抽象。安全校验、数据一致性、错误处理和当前任务明确要求的测试不能省略。生产代码不得用 unwrap 或 expect 掩盖可恢复错误。

每个任务先回复：任务理解、依赖检查、允许修改范围、最多 5 步计划。然后直接完成代码和测试，不要只给方案。完成后运行任务验收命令；只有全部通过才能勾选任务，并在“完成记录”写入修改文件、命令和结果。

最终回复固定包含：修改摘要、测试命令及结果、任务清单状态、剩余风险。不要提交 Git，除非我单独要求。
```

### 9.2 单任务执行提示词

每次只替换一个任务编号，例如先从 `TASK-001` 开始。

```text
执行 docs/DeepSwarm-Agent-开发任务清单.md 中的 TASK-001。

只做该任务；先检查其依赖和当前工作区，再按任务的目标、允许修改、禁止事项和验收标准完成实现。必须阅读设计文档中与当前任务直接相关的章节，不要自行改架构。若验收失败，继续修复当前任务，不要进入下一任务。全部通过后，仅更新当前任务的状态和完成记录。
```

### 9.3 只读复查提示词

编码模型报告完成后，可新开一次对话进行复查。复查模型默认不改代码。

```text
只读复查 TASK-001 的实现，不要修改文件。

先读取 docs/DeepSwarm-Agent-开发任务清单.md 中该任务的边界和验收，再检查 git diff、相关调用链和测试。重点找行为错误、状态不一致、安全漏洞、数据丢失风险、越界实现和缺失测试。运行该任务要求的验收命令。

先按严重程度列出问题，每条给出文件和行号；再列出已运行命令及结果。没有问题时明确写“未发现阻塞问题”，并说明仍未覆盖的风险。不要因为代码能编译就判定完成。
```

### 9.4 定点修复提示词

```text
修复 TASK-001 复查结果中的下列问题：

在这里粘贴问题列表。

只修复这些问题及其根因，不扩大任务范围，不重构无关代码。补最小回归测试，重新运行 TASK-001 的全部验收命令。全部通过后更新该任务的完成记录；不要开始下一个任务。
```

### 9.5 阶段验收提示词

```text
执行 Phase 1 阶段验收，只处理 TASK-015。

逐项核对该阶段所有前置任务是否为已完成，运行全局质量门禁和 TASK-015 的端到端场景。发现缺陷时只修复导致阶段验收失败的根因，不实现 Phase 2。输出每条验收标准的证据；只在全部通过后勾选 TASK-015。
```

## 10. 给人的使用顺序

1. 把第 9.1 节总控提示词发给编码模型一次。
2. 把第 9.2 节提示词中的编号改为当前第一个未完成任务。
3. 模型完成后，用第 9.3 节做一次只读复查。
4. 有问题时使用第 9.4 节定点修复，直到验收通过。
5. 每个 Phase 最后一项使用第 9.5 节做阶段验收。

不要一次把多个任务编号交给较弱模型。上下文越长不代表结果越稳，当前任务所需的最小充分上下文更可靠。
