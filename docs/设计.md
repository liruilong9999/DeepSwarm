# DeepSwarm 设计文档

## 设计目标

DeepSwarm 是一个使用 Rust(一种系统编程语言) 实现、面向 DeepSeek 的测试与评估工具，提供以下能力：

- 大规模多智能体协同测试：单个会话支持数百个 Agent(智能体) 并发，多个会话可同时运行。
- Fork(派生) 与继承模式：验证子智能体的状态隔离和信息传递。
- 工具链覆盖：集成文件、搜索、Shell(命令行)、Git、任务、PR、GitHub、自动化、计划、子智能体和 RLM(递归语言模型) 等工具，并可扩展。
- 多维测试：功能正确性、性能、提示注入、模糊测试和长稳测试。
- 可观测性：实时指标、结构化日志、分布式追踪和适用于 CI(持续集成) 的报告。
- 开发者工具：命令行、录制回放、模拟服务器和插件。

## 核心设计

### 多智能体协同与并发

- 每个 Agent 是独立的异步任务，拥有独立上下文、工具权限和对话历史。
- 一个 Session(会话) 容纳 1 至 500+ 个 Agent，由 `SessionManager` 管理生命周期。
- Fork 模式中，子 Agent 继承父 Agent 的快照（系统提示、历史消息、环境变量），后续独立执行。
- 继承模式可持续同步共享工作目录和计划板等指定状态。
- 基于 Tokio 异步运行时，使用 actor(参与者模型) 或异步任务组管理并发任务。
- 每个 Agent 配置工具调用并发数、内存上限和执行超时，防止资源耗尽。
- Agent 间通过消息队列或共享状态协调。

### 工具系统

```rust
trait Tool: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn parameters_schema(&self) -> serde_json::Value;
    async fn execute(&self, params: serde_json::Value, ctx: &ToolContext) -> ToolResult;
}
```

- 通过全局注册表按名称、类别和 Agent 权限查询、注入工具。
- 工具按文件、搜索、Shell、Git、任务、PR、GitHub、自动化、计划、子智能体和 RLM 分类。
- 默认使用无副作用的模拟实现；在外部环境就绪后可切换到真实实现。
- 所有调用经过拦截器链，以注入延迟、错误和限流，支持健壮性测试。

### 测试引擎

- 用例使用 YAML(一种数据序列化格式) 或 JSON(一种数据交换格式) 描述，支持变量、循环、条件和外部数据源。
- 断言覆盖结构（JSON Schema）、语义（关键词、正则、嵌入相似度）与性能（P95 延迟、吞吐量）。
- 负载支持渐增、稳定和突发阶段，并可按比例混合多个场景。
- 调度支持本地单进程，以及通过 gRPC(远程过程调用框架) 协调的多节点执行。

### 安全与鲁棒性

- 使用 `arbitrary` 和 `cargo-fuzz` 变异 Agent 输入及工具参数。
- 验证提示注入和越狱攻击下的内容安全过滤。
- 自动检测内存耗尽、文件描述符泄漏和死锁，并在超时后终止执行。

### 可观测性与报告

- 使用 `tracing` 输出 JSON 结构化日志，记录 Agent、Session 和 Trace 标识。
- 使用 Prometheus(监控系统) 和 OpenTelemetry(可观测性标准) 导出数量、成功率和延迟指标。
- 输出 JUnit XML、HTML 和 JSON 报告，并保留失败用例的请求、响应上下文。

### 扩展性

- 插件通过会话开始、工具调用和断言失败等生命周期钩子扩展，可动态加载 `.so` 或 `.wasm`。
- 支持从 CSV(逗号分隔值) 和 JSONL(换行 JSON) 读取批量测试向量。
- 模拟 DeepSeek API(应用程序接口) 服务可编程控制响应、延迟和错误率。

## 目录结构

```txt
deep-swarm/
├── Cargo.toml
├── README.md
├── docs/
│   └── 设计.md
├── config/
│   └── default.yaml
├── crates/
│   ├── deep-swarm-core/          # 测试执行、断言、报告、录制、调度、插件和指标
│   ├── deep-swarm-client/        # DeepSeek API 客户端、模型、流式解析和错误类型
│   ├── deep-swarm-agent/         # Agent、会话、生命周期、集群、派生、继承和策略
│   ├── deep-swarm-tools/         # 注册表、基础类型、拦截器及各类模拟工具
│   ├── deep-swarm-fuzzer/        # 模糊测试目标和生成器
│   ├── deep-swarm-bench/         # 负载模型和性能报告
│   ├── deep-swarm-mock-server/   # 模拟服务、处理器和响应模板
│   ├── deep-swarm-cli/           # run、record、replay、fuzz、bench、mock 和 init 命令
│   └── deep-swarm-plugins/       # 安全、延迟和自定义插件示例
├── tests/
│   ├── integration/              # 派生、工具链和并发集成测试
│   └── fixtures/                 # JSON/YAML 测试数据
├── benches/
│   └── assertion_bench/
├── examples/
│   ├── swarm_500_agents/
│   └── tool_orchestration/
└── tools/
    ├── ci/
    │   └── github-actions.yml
    └── docker-compose.yml
```

目录约定：

- 工具按类别组织，并由注册表动态发现和加载。
- `deep-swarm-agent` 独立管理 Agent 生命周期、派生、继承、通信和资源策略。
- `deep-swarm-core` 不依赖具体 Agent 或工具实现，通过 `Tool` trait(特征) 对接。

## 技术栈

| 范畴 | 选型 |
| --- | --- |
| 异步运行时 | Tokio |
| HTTP 客户端 | reqwest、hyper |
| 序列化 | serde、serde_json、serde_yaml |
| 日志与追踪 | tracing、tracing-subscriber、opentelemetry |
| 模糊测试 | cargo-fuzz、arbitrary |
| 性能基准 | criterion、tokio-metrics |
| 模拟服务器 | axum 或 warp |
| 命令行 | clap |
| 插件 | libloading 或 wasmtime |
