# DeepSwarm 设计文档

## 1. 设计目标

构建一个 Rust 实现的 DeepSeek 专属测试与评估 Harness，具备以下核心能力：

- 大规模多智能体协同测试：支持单个会话内数百个 Agent 并发，以及数百个独立会话的同时运行。
- Fork / 继承模式：模拟 Agent 的派生与上下文继承，验证子 Agent 的状态隔离与信息传递。
- 全工具链覆盖：集成超过 60 个内置工具（文件、搜索、Shell、Git、任务、PR、GitHub、自动化、计划、子智能体、RLM 等），并可扩展。
- 多维测试能力：功能正确性、性能（延迟/吞吐）、安全（提示注入、模糊测试）、稳定性（长稳、资源泄漏）。
- 可观测性：实时指标、结构化日志、分布式追踪、CI 友好的报告输出。
- 开发者友好：命令行工具、录制回放、Mock 服务器、插件体系。

## 2. 核心设计考量

### 2.1 多智能体协同与并发模型

- Agent 抽象：每个 Agent 为一个异步任务，拥有独立的上下文、工具权限、对话历史。
- Session 管理：一个 Session 可容纳 1～500+ Agent，通过 SessionManager 维护生命周期。
- Fork 模式：Agent A 派生出 Agent B，B 继承 A 的当前快照（系统提示、历史消息、环境变量），但后续完全独立。
- 继承模式：Agent B 除继承外，还可设定持续同步部分状态（如共享的工作目录、计划板），实现协作。
- 并发控制：基于 Tokio 异步运行时，使用 actor 模型或 async-task-group 管理海量 Agent，确保无阻塞。
- 资源隔离与限制：每个 Agent 可配置最大并发工具调用数、内存上限、执行超时，防止雪崩。
- 通信通道：Agent 间通过消息队列（如 tokio::sync::mpsc）或共享状态（如 Arc<RwLock<SharedWorkspace>>）进行协调。

### 2.2 工具系统设计

- 统一 Tool trait（Rust 伪代码）：

```rust
trait Tool: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn parameters_schema(&self) -> serde_json::Value;
    async fn execute(&self, params: serde_json::Value, ctx: &ToolContext) -> ToolResult;
}
```

- 工具注册表：全局唯一注册表，支持按名称、类别、Agent 权限动态查询与注入。
- 工具分类组织：文件、搜索、Shell、Git、任务、PR、GitHub、自动化、计划、子智能体、RLM、其他。
- 模拟与真实实现分离：Harness 中工具默认使用模拟实现（快速、无副作用），可切换为真实实现（需外部环境）。
- 工具调用拦截：所有工具调用通过拦截器链，可注入延迟、错误、限流，用于健壮性测试。

### 2.3 测试引擎

- 用例 DSL：YAML / JSON 定义测试场景，支持变量、循环、条件、外部数据源。
- 断言体系：
  - 结构断言：JSON Schema、字段存在性。
  - 语义断言：关键词匹配、正则、嵌入相似度阈值。
  - 性能断言：延迟 P95 < 目标值、吞吐量 > 基线。
- 负载模型：支持 ramp-up、稳定阶段、突发尖峰，可定义混合场景（多个用例按比例执行）。
- 执行调度：支持本地单进程、分布式多节点执行（通过 gRPC 协调）。

### 2.4 安全与鲁棒性

- 模糊测试：基于 arbitrary 对 Agent 输入、工具参数进行变异，集成 cargo-fuzz。
- 注入检测：测试 Prompt 注入、越狱攻击，验证内容安全过滤有效性。
- 资源耗尽防护：自动检测 OOM、文件描述符泄漏、死锁，超时强制终止。

### 2.5 可观测性与报告

- 结构化日志：tracing + JSON 格式，携带 Agent ID、Session ID、Trace ID。
- 指标导出：Prometheus / OpenTelemetry，监控 Agent 数量、工具调用成功率、延迟分布。
- 报告生成：JUnit XML、HTML Dashboard、JSON，附带失败用例的完整请求/响应上下文。

### 2.6 扩展性

- 插件系统：通过 trait 暴露生命周期钩子（on_session_start、on_tool_call、on_assertion_fail 等），支持动态加载 .so / .wasm。
- 外部数据驱动：从 CSV/JSONL 读取海量测试向量。
- 自定义 Mock 服务器：完整模拟 DeepSeek API，可编程控制响应逻辑、延迟、错误率。

目录设计说明：

- 每个工具独立文件夹：满足每个 rs 文件为一个文件夹的要求，便于后续为任一工具增加子模块、测试、文档，而不会影响其他工具。
- 工具按类别归入父文件夹：保持逻辑清晰，同时 registry 可根据类别进行动态发现和加载。
- 多智能体核心：DeepSwarmAgent 集中处理 Agent 生命周期、Fork/继承、通信、资源控制，可独立演进。
- 解耦测试引擎与业务：DeepSwarmCore 不依赖具体 Agent 或工具实现，通过 trait 对接，保证 Harness 可用于任何 LLM Agent 系统。

## 4. 技术栈与依赖

- 异步运行时：Tokio (multi-thread, work-stealing)
- HTTP 客户端：reqwest + hyper（HTTP/2 支持）
- 序列化：serde, serde_json, serde_yaml
- 日志/追踪：tracing, tracing-subscriber, opentelemetry
- 模糊测试：cargo-fuzz, arbitrary
- 性能基准：criterion, tokio-metrics
- Mock 服务器：axum 或 warp
- 命令行：clap
- 插件：libloading 或 wasmtime（动态加载）
